# Проверка интерфейсов INTERCITY — 23 октября 2026

Проверены web-интерфейсы пассажира, водителя и отдельной админки в Chromium. Основной размер приложения — 390×844; публичные формы дополнительно 360×640; админка — 1440×1000 и 360×740. Это управляемый проход по интерфейсу через браузер с визуальным просмотром снимков, проверкой доступных элементов и реальными запросами к локальному API. Проверка не заменяет испытания на физических Android/iOS устройствах.

## Изоляция

Локальная PostgreSQL-база `ui_review_20261023`, API `127.0.0.1:3100`, отдельные тестовые пользователи. Никакие проверочные поездки, пополнения, выплаты и кампании не создавались в production. Ключи платёжного провайдера и КГД в тестовом окружении отсутствуют. Созданная кампания не отправлялась.

## Исправления

- Прогресс документов водителя считается по трём обязательным загрузкам вместо фиксированных 75%; ранее сохранённый статус физического лица распознаётся при повторном входе в анкету.
- Вход пассажира прокручивается при открытой клавиатуре на экране 390×640 (300 пикселей занимает клавиатура); регрессионная проверка воспроизвела и устранила переполнение на 209 пикселей.
- Форма входа админки прокручивается на низком экране; длинные подписи не выходят за границы. Неуспешный вход пользователя без роли ADMIN очищает сессию.
- Обычная история пассажира больше не подставляет демонстрационные поездки при пустом ответе API. Для каждого фильтра показано своё пустое состояние. Демонстрационные записи остаются только в явно выбранном `/orders-history/seed`.
- Пассажирские и водительские бонусы показывают операции BONUS из API вместо статичных начислений/списаний. При сбое загрузки пассажиру доступен повтор.
- Сумма «К выплате» водителя берётся из `withdrawable`, как в форме вывода. Отсутствующая общая сумма заработка отображается как отсутствующая, а не как выдуманный ноль; подробности доступны в разделе «Заработок».
- Кнопка поднятия межгородского маршрута открывает список маршрутов вместо сообщения-заглушки.
- «Безопасность» открывает настоящую смену пароля: текущий пароль, новый, повтор, проверка 12 символов/72 байт, сохранение новых токенов. Ошибка текущего пароля не вызывает обновление токенов как при истечении сессии.
- Финансовый CSV реально скачивается. Налоговый CSV использует тот же механизм; вне web предусмотрено копирование. UTF-8 BOM позволяет открывать кириллицу в Excel.
- Кнопки решений по пополнениям/выплатам доступны только для PENDING; на телефоне действия расположены под текстом заявки.
- Переведены оставшиеся английские подписи в настройках, тарифах и финансовых разделах админки; добавлены проверки mounted для поздних ответов API.
- Убраны неподтверждённая отметка Premium и неверная версия профиля. Пункт, открывающий заказ, назван «Заказать поездку», а копирование шаблона обращения больше не называется его отправкой.

## Проверенные действия

Регистрация пассажира через форму; вход пассажира, водителя и администратора; защищённые маршруты; поиск пользователей; создание города; сохранение настройки; одобрение тестового пополнения и отклонение выплаты с последующим отображением транзакций; обязательные поля кампании; скачивание финансового CSV с проверкой содержимого; фильтры истории; раздельные валюты кошелька и заработка; предыдущий месяц; светлая/тёмная тема; пустой/неверный ввод в выводе реферальных средств; смена пароля через настоящий API, сохранение новых токенов и отказ старой сессии; переход к маршрутам; проверка обязательных городов; недействительная ссылка на поездку. Снимки и снимки дерева доступности сохранены локально в `output/ui-review/` (не входят в Git).

## Автоматические проверки

- Mobile: `flutter analyze` без замечаний; 324 теста пройдены, 9 пропущены платформенными условиями.
- Admin: `flutter analyze` без замечаний; 15 тестов пройдены, включая прокрутку входа на 360×640 и содержимое CSV.
- Backend: 72 теста пройдены, 18 интеграционных тестов пропущены без соответствующих переменных окружения. Для локального адресного индекса использован установленный `SQLITE3_BIN`.
- Обе web-сборки успешно собраны с локальным адресом API для браузерной проверки. Production-сборки должны использовать production URL, а не локальный.

## Ограничения, которые остаются

- Восстановление пароля по телефону сервер намеренно блокирует до настройки подтверждения личности; SMS/OTP нельзя считать проверенным.
- Телефон поддержки не настроен. Копирование шаблона не отправляет обращение оператору.
- Выбор наличных/перевода/бонусов в профиле показывает подсказку; окончательный способ оплаты выбирается при оформлении заказа. Постоянный способ по умолчанию не реализован.
- Не проверялись реальные банковские списания/выплаты, государственная отправка и уплата налогов, фоновые push на физических устройствах, камера и разрешения реального телефона. Эти проверки требуют соответствующих подключений и устройств.
- Язык и единицы в обновлённом профиле остаются информационными пунктами; полноценное переключение языка всего интерфейса не реализовано.
- Первоначально локальный процесс Node не использовал сетевой прокси и возвращал ROAD_ROUTE_UNAVAILABLE/503. После подключения EnvHttpProxyAgent только к тестовому процессу пройден настоящий локальный цикл через API: расчёт → создание → принятие → прибытие → начало → завершение → оценка 5. Серверный итог: 1 поездка, доход 850 ₸, комиссия 85 ₸, после комиссии 765 ₸. История подтверждена и в браузере. Production отдельно успешно рассчитал дорожный маршрут 2,2899 км и стоимость 550 ₸; реальных поездок на production не создавали.
- Старый `scripts/smoke_prod_core.sh` не проходит на новом пустом кошельке водителя: требуется первоначальное пополнение для выхода на линию. Это ограничение сценария проверки, не основание отключать проверку баланса в приложении.
