# Активная поездка, маршруты и доставка — 06.11.2026

Исправления по скриншотам водителя и пассажира:

- Подтверждённое сервером изменение статуса больше не ждёт расчёта маршрута и обновления профиля. «На месте» переходит в «Начать поездку» после успешного POST; ошибка самого POST по-прежнему отображается.
- Очередь по требованию пользователя исключена. Собственный маршрутизатор выполняет до восьми независимых расчётов параллельно; одинаковые запросы объединяются и кешируются. Девятый новый расчёт при полной занятости получает явную ошибку, не ждёт в очереди и не прерывает остальные. Память маршрутизатора увеличена в пределах текущего сервера: heap 1024 MiB, контейнер 1536 MiB, 1,5 CPU. Лимиты проверены на реальном движке и графе OSM в контейнере с такими же ограничениями. Внешние платные или публичные демонстрационные источники не включаются.
- Карта водителя использует результат расчёта активного заказа, без второго независимого запроса на каждое изменение GPS. Незавершённый расчёт одной фазы поездки не дублируется обновлениями позиции.
- Если координаты водителя получены и до подачи менее 50 метров, отображается сообщение о близости. Дорожная линия не выдумывается. Пассажир получает сообщение «Водитель рядом». Это не заменяет подтверждение фактического прибытия.
- Значения полей координат по умолчанию не считаются местоположением водителя. Большая коррекция камеры выполняется сразу вместо анимации через промежуточные города и загрузки их плиток.
- Из межгорода можно вернуться на главный экран без отмены: бронь сохраняется и открывается из карточки. При наличии даты заказа отображается запланированный выезд. Отмена остаётся отдельным действием.
- Для доставки дата и время явно выбираются через общий элемент выбора. До выбора они не подтверждены. Проверка проходит через настоящие диалоги даты/времени и сравнивает выбранное значение с отправленным в создание заявки.

Проверки: сборка backend; тесты поиска, политики источников, параллельного расчёта, дорожной геометрии; создание заказа при отказе/восстановлении маршрутизатора в локальной транзакции с откатом; Flutter analyze, полный набор Flutter-тестов и браузерная проверка release-сборки с подставными бизнес-данными и настоящими плитками.

На предыдущей версии публичный обычный маршрут по Усть-Каменогорску вернул HTTP 200 за 1,17 с, а близкие точки подачи — HTTP 503 за 1,41 с. Доступные ресурсы текущего VPS проверены: 2 CPU, 3915 MiB RAM, 2568 MiB доступно, 23 GiB свободно на диске; маршрутизатор использовал около 110 MiB из лимита 640 MiB. Новые службы/серверы не добавлены.

Ограничения: ошибка внешних данных или исчерпание параллельной ёмкости движка остаётся явной ошибкой с возможностью повтора. Ручной адрес без геоточки не превращается в достоверный маршрут. Запрет геолокации браузером требует разрешения пользователя для сайта; включение GPS в системе само по себе его не отменяет. Пользовательские заказы и учётные записи для проверки в production не создаются и не редактируются.


Дополнение по доставке и грузовым:

- В доставке город передаётся отдельно от ручного адреса. Для ближайших городских доставок достаточно действительных GPS-координат водителя, даже если связь с каталогом городов ещё не записана. Будущие даты не исключаются из списка.
- При создании доставки отправляется push подходящим одобренным водителям с включённым режимом доставки; междугородние направления учитывают маршрут и день. Уведомление ведёт в список доступных заявок. Одновременно Firebase вызывается максимум для четырёх получателей. В открытом приложении новая доступная доставка отмечается звуком и сообщением один раз за сеанс; повторный SSE не повторяет сообщение.
- У грузового заказа можно явно выбрать город подачи. Поиск точки A использует выбранный город и отбрасывает результаты дальше 60 км от его центра; точка B сохраняет возможность поиска в другом городе. При отсутствии GPS город выбирается вручную.
- При ошибке расчёта пассажиру показывается, что время пока недоступно, вместо бесконечного «Рассчитываем…». После успешного повтора ETA снова появляется.
- Убрана повторная строка оплаты в доставке.

Дополнительные проверки: 35 backend-проверок без внешних отправок, локальная транзакционная проверка видимости будущей доставки и отключённого режима, Flutter-регрессии выбранного города грузового заказа, диалогов даты доставки, ошибки/восстановления ETA и однократного сообщения о новой доставке. В read-only проверке production подтверждено, что отменённая заявка DELIVERY_CITY содержала улицу в поле fromCity; пользовательские записи не изменялись.

Финальные локальные результаты: Flutter analyze — без замечаний; 403 Flutter-теста пройдены, 9 ранее помеченных пропущены; 35 backend-проверок пройдены; 2 интеграционные проверки локальной БД пройдены с откатом. Браузер: статус DRIVER_ARRIVED после нажатия «На месте», 0 запросов маршрута для близкой подачи, 30 успешных запросов плиток, фактическое изображение карты проверено по пикселям (1102 цвета в контрольной области), 0 ошибок JavaScript. Это проверки на подставных бизнес-данных, а не операции с реальными заказами.


## Пятикратная проверка перед публикацией

По требованию пользователя все повторные проверки закончены до отправки новой версии:

- Пять полных прогонов Flutter: в каждом 403 успешных теста и те же 9 ранее пропущенных.
- Пять прогонов 35 backend-проверок поиска, политики источников, параллельного расчёта и выбора получателей push; пять прогонов двух интеграционных проверок локальной БД с откатом.
- Пять проверок кнопки «На месте» в Chromium; пять циклов город/аукцион в одном сеансе; пять пересечений GPS границы 50 м в одном сеансе. При каждом удалении от подачи заново загружается маршрут, без зависшего состояния кеша.
- Пять одновременных наборов городских/междугородних маршрутов KZ/RU на настоящем BRouter/OSM, затем пять наборов по восемь одновременных маршрутов Москва—Санкт-Петербург (40 расчётов, около 712 км каждый). Все ответы содержат дорожную геометрию. Очереди приложения нет.
- При лимите контейнера 1536 MiB и 1,5 CPU: максимум памяти около 537 MiB, OOM и перезапусков нет. Смешанная нагрузка: городские 0,1–2,4 с; одиночный дальний в смешанной группе 6,7–11 с. При восьми дальних одновременно — 24,6–39,7 с. Это локальный нагрузочный тест, а не гарантия задержки на production или любом устройстве.
- Пять проверок резервной копии/переключения/отката выпуска на заглушках Docker; устаревший тестовый пакет дополнен манифестом маршрутизатора без сетевого скачивания. Основной скрипт развёртывания не изменялся.

Конечная вместимость текущего сервера не позволяет обещать мгновенное построение неограниченного числа длинных маршрутов: максимум восемь новых расчётов параллельно; кешированные ответы не занимают вычислительные слоты.
