# Обязательное разрешение геолокации в веб-версии

После входа отсутствие разрешения геолокации блокирует продолжение: полноэкранное окно без кнопки закрытия, фон недоступен мыши и клавиатуре. Регистрация, вход, восстановление пароля и первичная проверка личности остаются доступны до настройки GPS. Уведомления не блокируют работу — это сохраняет доступность iPhone, где Web Push поддерживается не во всех режимах.

Кнопка «Проверить доступ к геолокации» действительно запрашивает координаты по нажатию. При запрете выводит результат и точные инструкции браузера и телефона; открыть системные настройки сайта автоматически веб-страница не может. Включённый GPS телефона не означает разрешение для сайта. Автоматического бесконечного вызова системного диалога нет.

После выдачи доступа окно снимается. Состояние разрешения браузера и фактический ответ геолокации синхронизированы; тайм-аут/недоступность GPS не считаются отказом. Повторное открытие блокировки происходит при отзыве разрешения. Разрешение хранит браузер, отдельно для каждого устройства/сайта. При отсутствии Permissions API учитывается фактическое получение координат приложением.

Если разрешение выдано во время завершения предыдущего запроса GPS, запрос повторяется после его завершения, если адрес ещё пуст. Ручной адрес сохраняется. Обратное определение адреса и города делит один запрос и одну повторную попытку при временной сетевой ошибке/тайм-ауте/HTTP 5xx (350 мс); ошибки 4xx не повторяются. Неуспешные ответы не кэшируются. Координаты не подменяются выдуманным адресом.

Проверки перед публикацией: Flutter analyze, release web build, пять прогонов браузерного набора с обязательным экраном, отказом/успехом, повторным открытием, отзывом разрешения, GPS timeout, Safari без Permissions API, недоступным push на iPhone, защищёнными маршрутами, скрытой вкладкой и устаревшим ответом. Пять полных прогонов Flutter: 406 успешных тестов и 9 существующих пропусков в каждом. В собранном Flutter Web 5 раз проверены оба сценария: разрешение GPS после отказа с имитацией HTTP 503 при первом определении адреса (успешная повторная попытка) и сохранение ручного адреса; 10 сценариев без ошибок JavaScript и без перезагрузки. На действующем API пять запросов обратного геокодирования одной тестовой точки вернули подтверждённые город и адрес (0,49–3,08 с). Тестовые аккаунты и ответы бизнес-API изолированы от production.

Внешние ограничения остаются: браузер не открывает системный запрос после постоянного запрета без изменения настроек; скорость/точность GPS зависят от телефона, название адреса — от сети и данных геосервиса. Окно не имитирует успешное определение адреса.
