# Обязательное разрешение геолокации в веб-версии

После входа отсутствие разрешения геолокации блокирует продолжение: полноэкранное окно без кнопки закрытия, фон недоступен мыши и клавиатуре. Регистрация, вход, восстановление пароля и первичная проверка личности остаются доступны до настройки GPS. После уточнения пользователя разрешение уведомлений тоже обязательно там, где браузер поддерживает Web Push. На iPhone в режиме без Web Push невозможный запрос не блокирует работу. Ошибка регистрации токена при уже выданном разрешении не блокирует продолжение.

Кнопка «Проверить доступ к геолокации» действительно запрашивает координаты по нажатию. При запрете выводит результат и точные инструкции браузера и телефона; открыть системные настройки сайта автоматически веб-страница не может. Включённый GPS телефона не означает разрешение для сайта. Автоматического бесконечного вызова системного диалога нет.

После выдачи доступа окно снимается. Состояние разрешения браузера и фактический ответ геолокации синхронизированы; тайм-аут/недоступность GPS не считаются отказом. Повторное открытие блокировки происходит при отзыве разрешения. Разрешение хранит браузер, отдельно для каждого устройства/сайта. При отсутствии Permissions API учитывается фактическое получение координат приложением.

Если разрешение выдано во время завершения предыдущего запроса GPS, запрос повторяется после его завершения, если адрес ещё пуст. Ручной адрес сохраняется. Обратное определение адреса и города делит один запрос и одну повторную попытку при временной сетевой ошибке/тайм-ауте/HTTP 5xx (350 мс); ошибки 4xx не повторяются. Неуспешные ответы не кэшируются. Координаты не подменяются выдуманным адресом.

Проверки перед публикацией: Flutter analyze, release web build, пять прогонов браузерного набора с обязательным экраном, отказом/успехом, повторным открытием, отзывом разрешения, GPS timeout, Safari без Permissions API, недоступным push на iPhone, защищёнными маршрутами, скрытой вкладкой и устаревшим ответом. Пять полных прогонов Flutter: 406 успешных тестов и 9 существующих пропусков в каждом. В собранном Flutter Web 5 раз проверены оба сценария: разрешение GPS после отказа с имитацией HTTP 503 при первом определении адреса (успешная повторная попытка) и сохранение ручного адреса; 10 сценариев без ошибок JavaScript и без перезагрузки. На действующем API пять запросов обратного геокодирования одной тестовой точки вернули подтверждённые город и адрес (0,49–3,08 с). Тестовые аккаунты и ответы бизнес-API изолированы от production.

Внешние ограничения остаются: браузер не открывает системный запрос после постоянного запрета без изменения настроек; скорость/точность GPS зависят от телефона, название адреса — от сети и данных геосервиса. Окно не имитирует успешное определение адреса.

## Яндекс Браузер и уведомления

Первая сборка 42347227912 отменена до production после уточнения браузера. Добавлены инструкции Яндекса для разрешений Android, геолокации и уведомлений от сайтов. Нативный Notification.requestPermission вызывается прямо в обработчике нажатия, до Dart/Firebase и других await. Поддержаны Promise и старый callback API. Разрешение ОС отделено от регистрации токена Firebase: ошибка токена не выдаётся за отказ в разрешении. Есть ограничение ожидания и явное сообщение, если браузер не открыл диалог. Фоновое событие заказа/сообщения не запрашивает новое разрешение, а вспомогательные запросы проверяют наличие текущего пользовательского нажатия.

Запрос уведомлений доступен и в обычной вкладке браузера. Экран без кнопки закрытия остаётся до разрешения, если Web Push поддерживается. Он не позволяет обойти обязательную геолокацию. После разрешения окно исчезает; отдельную подсказку повторного подключения токена можно закрыть на сутки. Системный запрос возможен только по пользовательскому нажатию; после постоянного запрета сайт не может автоматически заставить браузер открыть его заново.

Источники инструкций: https://yandex.ru/support2/browser-mobile-android-phone/ru/install/permissions и https://yandex.ru/support2/browser-mobile-android-phone/ru/personal-settings/notifications . У Яндекса отдельный общий запрет предложений уведомлений от сайтов; при таком запрете страница не может принудительно открыть системное окно.

Дополнительные проверки: сценарии API в Chromium с User-Agent Яндекс Браузера, Promise/callback запросом уведомлений и проверкой пользовательского нажатия, запретом и общим отключением диалогов, неудачной регистрацией токена. Это эмуляция API и поведения страницы, не запуск Android-версии Яндекс Браузера на реальном телефоне.

Финальная проверка интерфейса: 5 прогонов по 16 групп сценариев, включая обязательные экраны GPS/уведомлений, отказ без возможности закрытия, настоящий вызов Notification API в обработчике клика, callback-only API, молчаливый отказ браузера и ошибку регистрации токена после выданного разрешения. В собранном приложении дополнительная инструментальная проверка подтверждает: один вызов Notification API с активным пользовательским нажатием и один вызов Dart-мостика; нативный API в этом тесте подменён, системное окно реального Android/Яндекс Браузера не эмулируется.
