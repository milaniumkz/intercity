# Уведомления водителя

В браузере звук активируется нажатием «Выйти на линию». В этот момент запрашивается разрешение на уведомления и сохраняется FCM-токен текущего аккаунта. Если браузер ранее запретил уведомления, разрешите их в настройках сайта и повторно выйдите на линию. На iPhone веб-push требует добавления сайта на домашний экран.

Для серверного push используется Firebase HTTP v1, а не отключённый legacy API. Добавьте JSON сервисного аккаунта проекта inter-city-pkzpps в GitHub Actions secret `FIREBASE_SERVICE_ACCOUNT_JSON` с правом отправки FCM. Не помещайте ключ в исходники или чат. При публикации он передаётся отдельно от архива и сохраняется в защищённой конфигурации сервера; резервная копия конфигурации сохраняется до изменения. Альтернативно backend поддерживает `GOOGLE_APPLICATION_CREDENTIALS` с доступным внутри контейнера файлом.

Для браузерного push настройте GitHub Actions secret `INTERCITY_FIREBASE_WEB_VAPID_KEY` (публичный ключ Web Push из Firebase Cloud Messaging). Без серверного сервисного аккаунта push при закрытом приложении не доставляется; звуковой сигнал и получение заказа при открытом приложении работают отдельно.

Публикация выводит только наличие серверной конфигурации, без её значений. Ошибки Firebase логируются с HTTP-статусом, без токенов и ключей. Время жизни push ограничивается сроком предложения заказа.


Звуковой сигнал заказа встроен в assets, Android raw resources и bundle iOS. В открытом приложении он повторяется до решения или истечения предложения. Android использует отдельный канал «Новые заказы водителя» с максимальной важностью, вибрацией и собственным звуком; iOS — собственный звук и уровень time-sensitive. Истечение предложения закрывает окно и удаляет локальное уведомление. Для получения нового встроенного звука на Android/iOS нужна новая сборка приложения; публикация веб-версии не обновляет установленные нативные приложения. ОС определяет доставку в фоне и применение пользовательских настроек звука, Focus и разрешений.

## Статусы поездки пассажира

Нажатие «Заказать» активирует браузерный звук и запрашивает разрешение на уведомления. При назначении водителя, прибытии и начале поездки звучит сигнал; повторное получение того же события через FCM, SSE или опрос не повторяет звук. Обычный запуск приложения не запрашивает разрешение автоматически. Для звука браузер требует предшествующего действия пользователя; настройки громкости и сайта остаются под управлением пользователя.

После статуса `DRIVER_ARRIVED` пассажиру доступна кнопка «Выхожу». Сервер проверяет владельца поездки и статус, сохраняет `passengerLeavingAt` и отправляет водителю realtime-событие и push. Повторные и одновременные запросы не создают новых уведомлений. Опрос активной поездки восстанавливает сообщение при разрыве realtime-соединения. С началом поездки кнопка исчезает.

Мобильные браузеры получают локальные уведомления через service worker. Для фоновой доставки по-прежнему требуются оба ключа Firebase. `VPS Ops → status → notifications` показывает только наличие и корректность настройки, без значений ключей.
