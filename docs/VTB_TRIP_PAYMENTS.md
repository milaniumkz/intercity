# ВТБ: оплата пассажирских поездок и привязка карты

## Режим
Только тестовый шлюз https://vtbkz.rbsuat.com/payment/rest/. Боевые банковские данные не включаются.
Российский профиль и поездки в RUB. В приложении цена в рублях; банк принимает KZT по фиксированному курсу 1 RUB = 7 KZT. Сумма KZT фиксируется в платеже, возврат использует её же.
Подтверждение тестовой картой не означает готовность боевого эквайринга для всех российских карт.

## Поездка
- Фиксированная цена CITY/CARGO/DELIVERY: создание заявки не создаёт банковский платёж. Платёж создаётся атомарно с фактическим принятием водителем; затем сразу запускается оплата. Автопредложение заказа водителю само по себе не запускает списание.
- Городской аукцион и межгород: подготовка после выбора предложения, по принятой цене водителя, без списания предварительной цены заявки.
- Карта выбирается в профиле. Без сохранённой карты открывается защищённая форма ВТБ с вводом карты.
- Для сохранённой карты register.do получает clientId и bindingId. Один раз вызывается paymentOrderBinding.do без CVC (CIT, tii=F). Если банк требует CVC/3DS, используется банковская форма для того же заказа, без повторной автоматической попытки.
- Начало поездки запрещено, пока аутентифицированный getOrderStatusExtended.do не подтвердит orderNumber, точную сумму KZT, currency=398, orderStatus=2 и actionCode=0. Редирект и callback не служат доказательством оплаты.
- При завершении: изменение статуса, доход водителя, существующие комиссии/удержания и финансовая история выполняются одной транзакцией БД. Успешное списание до поездки не зачисляет деньги водителю.
- При отмене до начала: refund.do для списанной суммы; reverse.do для холда; decline.do для ещё не оплаченной банковской формы. Возврат имеет постоянный externalRefundId; статус REFUNDED ставится только после банковского подтверждения полного возврата.
- Повторы, закрытая форма, сбой связи и callback не создают новую оплату. Работа продолжается фоновым обработчиком. После трёх подтверждённых банковских отказов три разные попытки сохраняются в истории, заказ атомарно переводится на наличные. Водитель и пассажир получают push и события интерфейса. Неизвестный результат/тайм-аут не считается отказом и не запускает новый платёж. При запросе CVC форма остаётся у пассажира; это само по себе не банковский отказ.

## Привязка
Путь: профиль пассажира → банковские карты → «Добавить карту · 1 ₸ с возвратом».
Номер карты и CVC вводятся только на стороне ВТБ. Пользователь выбирает сохранение карты на банковской странице.
Используется отдельный register.do с clientId пользователя и суммой 100 тиын (1 ₸). После оплаты выполняется автоматический refund.do с постоянным идентификатором, затем проверка суммы возврата и синхронизация связок. Этот платёж не пополняет кошелёк.
В БД хранится зашифрованный bindingId, хеш и последние четыре цифры, без PAN/CVC. Пользователь может выбрать карту по умолчанию или отвязать её; карту текущего незавершённого платежа отвязать нельзя.
Без прав банка привязка отключена до списания 1 ₸. Доступность прав повторно проверяется, результат кешируется до пяти минут.

## Реальное ограничение мерчанта, проверено 25.11.2026
getBindings.do для intercity-api: errorCode=5, «Доступ запрещён».
Привязка без платежа через VERIFY + FORCE_CREATE_BINDING: errorCode=13.
В размещённой форме обычного платежа параметр сохранения карты скрыт; после успешной оплаты bindingInfo отсутствует.
Проверочный платёж 1 ₸ и его возврат прошли в тестовом шлюзе. Сохранение и повторное списание с сохранённой карты нельзя считать проверенными на банке, пока он не выдаст права.

### Текст запроса в ВТБ
Для тестового мерчанта intercity / API-пользователя intercity-api просим включить создание банковских связок (clientId/bindingId), отображение сохранения карты на платёжной странице, getBindings.do, unBindCard.do и paymentOrderBinding.do.
Нужны обычные CIT-платежи по сохранённой карте с CVC в форме банка, а при разрешённом банком сценарии — без повторного CVC. Просим подтвердить настройки 3DS и допустимый сценарий.
Просим также разрешить VERIFY + FORCE_CREATE_BINDING для привязки без списания либо подтвердить использование проверочного платежа 1 KZT с автоматическим возвратом.

Это подготовленный текст; сообщение банку автоматически не отправляется.

## API
- GET /payments/cards — провайдер, карты (только id/last4/isDefault), cardBindingAvailable и состояние последней привязки.
- POST /payments/cards/bind — отдельная проверка 1 KZT; при запрете банка операция не создаётся.
- POST /payments/cards/sync — аутентифицированная синхронизация банковских связок.
- PATCH /payments/cards/:id/default — выбор собственной активной карты.
- DELETE /payments/cards/:id — отвязка собственной карты после ответа банка.
- POST /payments/vtb/trips/:kind/:tripId/checkout — состояние и форма оплаты собственной поездки; kind CITY или INTERCITY. Сумма берётся только из сохранённой поездки, не из тела запроса.
- GET /payments/vtb/trips/return?kind=...&tripId=... — возврат в конкретный заказ или профиль; не подтверждает платёж.
- GET/POST /payments/vtb/trips/callback — сигнал фоновому обработчику, не доверенный статус.
В ответе заказа cardPayment содержит provider=VTB_SANDBOX, status, amount (RUB), bankAmountMinor (KZT), conversionRate, paymentUrl, paidAt.
