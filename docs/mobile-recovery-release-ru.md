# Google и Apple для InterCity

Аккаунты, привязки и пароли хранятся на сервере InterCity. Firebase Authentication не используется. Провайдер открывается в системном браузере. После подтверждения пользователь возвращается в открытое приложение. Сервер сверяет подпись, аудиторию, срок и одноразовый запрос, затем выдаёт разрешение на смену пароля на пять минут.

В Google Cloud создайте OAuth-клиент типа «Веб-приложение», задайте согласие и разрешённый HTTPS URL перенаправления. В Apple Developer настройте Sign in with Apple, Services ID, привязанный App ID и тот же домен и Return URL. Для Google и Apple адрес возврата должен в точности совпасть с RECOVERY_OAUTH_CALLBACK, например https://api.intercity.89-207-255-27.sslip.io/api/auth/recovery/callback. Зарегистрируйте адрес у обоих провайдеров.

В защищённом окружении сервера задайте GOOGLE_RECOVERY_CLIENT_IDS (первый элемент — используемый веб-клиент), GOOGLE_RECOVERY_CLIENT_SECRET, APPLE_RECOVERY_CLIENT_IDS (Services ID), APPLE_RECOVERY_CLIENT_SECRET (подписанный Apple client secret JWT) и RECOVERY_OAUTH_CALLBACK. Обновляйте Apple client secret до истечения срока. Не добавляйте секреты в мобильное приложение, Git или чат.

На Android и iPhone проверьте привязку после регистрации и из профиля, отказ от привязки, восстановление через каждый провайдер, отмену авторизации, просроченный запрос, невозможность повторного использования кода и отзыв старой сессии. Отдельно проверьте получение кода в WhatsApp для обычного тестового аккаунта и обращение в поддержку. Публикацию в магазинах выполняйте после этих проверок.
