# ВТБ: тестовый контур и пополнение рублёвого баланса

В приложении сумма указывается в RUB. Банку передаётся KZT (ISO 398).
Фиксированный курс: **1 RUB = 7 KZT**. Пополнение 100.00 RUB:
- банк получает amount=70000 (700.00 KZT);
- после подтверждённого списания на баланс приложения поступает 100.00 RUB.

## Подтверждение и учёт
Зачисление создаётся только после серверного запроса ВТБ: orderStatus=2, actionCode=0,
совпали номер заказа, currency=398 и сохранённая сумма KZT.
Ни redirect, ни поля callback сами по себе оплату не подтверждают.
В одной транзакции БД сохраняются статус/creditedAt, увеличение Wallet.moneyRub,
APPROVED TopupRequest с provider=VTB_SANDBOX и WalletTransaction типа TOPUP_DEMO_CREDIT.
Повторные callbacks, проверки и фоновые запросы не создают второе зачисление.
Другие валюты и бонусы не меняются. Отмена/ошибка/несовпадение суммы не пополняют баланс.

Фоновая проверка каждые 30 секунд обрабатывает незавершённые пополнения,
даже если пользователь закрыл страницу банка. Кошелёк обновляется после проверки и возврата.

## Переключатель тестового зачисления
VTB_SANDBOX_WALLET_CREDITS_ENABLED по умолчанию false.
Для этого сервера включён через walletCreditsEnabled=true в sealed-конфигурации;
это открытый переключатель, логин/пароль остаются зашифрованными.
Флаг сохраняется в каждой новой операции. Старые операции, созданные без зачисления,
автоматически не пересчитываются. Уже созданные операции сохраняют своё назначение.

## Маршрутизация
- Российский профиль: «Пополнить» → RUB → подтверждение суммы KZT → ВТБ.
- Российский пассажир: «Карта» поездки → отдельный TRIP_TEST; такая проверка не пополняет кошелёк и не оплачивает реальный заказ.
- Казахстан: существующие Kaspi/Kassa24.
- Используется только тестовый банк. Боевые реквизиты и endpoint не подключены.

## API (префикс /api)
- GET /wallet/vtb/sandbox — доступность, creditsWallet и последняя операция TOPUP.
- POST /wallet/vtb/sandbox/payments — amount в RUB, currency=RUB, purpose=TOPUP или TRIP_TEST, requestKey для идемпотентности.
- POST /wallet/vtb/sandbox/payments/:id/check — проверка собственной операции.
- GET/POST /payments/vtb/sandbox/callback — сервер перепроверяет банк; POST подтверждается HTTP 200.
- GET /payments/vtb/sandbox/return — возврат в кошелёк или форму поездки.
Ответ операции содержит status, purpose, amount, bankAmount, conversionRate,
creditsWallet (назначение операции) и creditedAt (зачисление завершено).

## Секреты и развёртывание
infra/vps/vtb-sandbox.sealed.json содержит RSA-OAEP-SHA256 ciphertext.
Закрытый ключ только на VPS: shared/vtb-sandbox-secrets/private.pem (0600).
Деплой сравнивает исходники с рабочим сервером, создаёт backup и атомарно устанавливает настройки.
Новые поля БД добавляются без пересчёта прежних платежей.
