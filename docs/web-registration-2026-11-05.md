# Обновление регистрации и допуска водителя

При нажатии «Режим водителя» статус запрашивается заново. Открытая форма регистрации проверяет одобрение каждые 8 секунд и после возвращения на страницу; активному водителю с завершённой сверкой документов вместо повторной регистрации показывает кнопку перехода в водительский режим.

Реферальный код — скрытые данные ссылки, а не редактируемое поле. Изменение приглашения в той же вкладке обновляет значение в форме и на посадочной странице. Для запроса регистрации фиксируется код, действующий в момент отправки. После успешного ответа регистрации временное значение очищается из формы и браузера до автоматического входа: сбой последующего входа не оставляет чужое приглашение следующему пользователю. Сохранённый сервером `referredBy` остаётся для бонусов.

Старое приглашение, найденное только в браузерном хранилище, удаляется лишь после ответа `/auth/referral-validity` с `valid=false`; ошибка сети не считается невалидностью. Код текущей ссылки не заменяется старым и не удаляется автоматически. Проверка валидности не раскрывает сведения о пригласившем и не создаёт аккаунт.

Проверено: 380 Flutter-тестов, включая обновление одобрения без перезагрузки, смену приглашения в открытой форме, очистку после регистрации при сбое входа и очистку недействительного старого приглашения. Проверка API валидности не изменяет код в базе.
