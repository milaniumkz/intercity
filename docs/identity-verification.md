# Видеопроверка и восстановление доступа InterCity

## Пользовательский путь

1. Регистрация: телефон и пароль, без SMS. После регистрации — отдельное согласие на биометрическую обработку, текущий пароль и видео с фронтальной камеры.
2. Камера сначала показывает предварительный просмотр с овалом лица и русскими голосовыми подсказками женским нейроголосом Irina из встроенных аудиофайлов. Пользователь нажимает «Начать запись» и выполняет два случайных задания за 14 секунд при первичной регистрации; три задания за 20 секунд при восстановлении. Выбор видео или фотографии из галереи не предусмотрен.
3. Пассажиру сохраняется зашифрованный эталон для восстановления пароля. У водителя отдельное согласие также охватывает сверку с удостоверением личности.
4. «Забыли пароль»: телефон → новая видеопроверка → сравнение с ранее созданным эталоном → новый пароль. Первичный эталон через этот путь создать или заменить нельзя.
5. Несовпадение запрещает сброс. При первичной привязке сомнительная уверенность означает отказ с предложением новой записи, без ручного рассмотрения и без общего лимита попыток. Защита от частых технических запросов сохраняется. При восстановлении сомнительная уверенность требует ручного решения. Успешное разрешение на сброс действует 10 минут, используется один раз, аннулирует прежние сеансы.
6. Действующий пользователь без эталона проходит первичную проверку при входе. Административные аккаунты исключены из пассажирского восстановления.

Номер телефона используется как логин. Этот механизм не доказывает владение телефонным номером; SMS не добавлен по требованию владельца продукта.

## Водители и документы

В разделе «Документы и проверка» загружаются удостоверение, водительское удостоверение и техпаспорт. Фото в удостоверении сравнивается с видеоэталоном. Это сравнение лиц, а не государственное подтверждение подлинности документа. Итоговый допуск водителя по-прежнему требует проверки администратора.

Из техпаспорта читаются только данные машины: госномер, марка, модель и год. Владелец автомобиля не подтверждается. При уверенном чтении данные заменяют сведения о машине в профиле и активном Vehicle. Нечитаемые поля, неизвестная модель, противоречия сторон и сомнения требуют ручного рассмотрения; произвольные значения не угадываются.

Парсер поддерживает русские/казахские/английские подписи полей, распространённые RU/KZ форматы госномеров и каталог автомобилей. Полный автоматический охват всех исторических бланков не заявляется: неизвестный бланк поступает администратору. В ручной очереди можно прочитать обе стороны и указать четыре поля машины. Сведения владельца не используются.

Смена документа или данных машины делает прежнюю привязку недостаточной для работы. Повторная проверка того же техпаспорта восстанавливает авторитетные сведения машины. Паспорт другого пользователя не принимается. Явное несовпадение лица нельзя одобрить через очередь сомнительных результатов.

## Собственный сервер

- Изолированный сервис `services/identity`, внутренний Docker network, без опубликованного порта и без внешних запросов при обработке.
- OpenCV YuNet/SFace: одно лицо и сравнение 1:1. MediaPipe: серверное распознавание действий. Две локальные MiniFASNet-модели: признаки предъявления фотографии/экрана.
- Задания выдаются сервером и привязаны к одноразовому сеансу; сервер сам декодирует запись и проверяет действия/временную последовательность. Учитывается WebM без заголовка длительности из браузерного MediaRecorder.
- Блокируются повтор точно того же файла и практически одинаковые последовательности кадров в пределах одного аккаунта. Временные сигнатуры зашифрованы; межпользовательский поиск лиц не выполняется.
- Документы обрабатываются локально, OCR — Tesseract rus/kaz/eng. Государственные базы и сторонние биометрические API не используются.
- Модели закреплены SHA256; лицензии/происхождение в `services/identity/models` и `vendor/manifest.json`. PyTorch нужен только для воспроизводимого экспорта PAD, в рабочем контейнере его нет.

Проверки повышают устойчивость к фото, воспроизведению и подмене, но не дают гарантии обнаружения любой глубокой подделки или виртуальной камеры. Модель не аттестована; показатели FAR/FRR на целевой аудитории и устройствах не измерены. Нельзя называть её сертифицированной идентификацией. До расширения использования нужны реальные положительные и атакующие записи с согласия участников; сомнительные случаи остаются ручными.

## Хранение и доступ

AES-256-GCM с привязкой к userId: эталон, контрольный снимок, сигнатура и материалы ручной проверки. Ключ — `technical-data/identity/key.bin`, права 0600. Файлы находятся вне uploads и публичных веб-каталогов. Утрата ключа не вызывает незаметное создание нового ключа поверх существующих данных: нужна исходная резервная копия.

Успешная первичная видеозапись сохраняется зашифрованной вместе с эталоном до удаления аккаунта, с отдельным согласием версии v2. Автоматически обработанная новая запись восстановления не сохраняется. В контейнере оно временно декодируется в tmpfs. Материалы ручной проверки удаляются из рабочего хранилища через 7 дней; решение доступно в течение 24 часов. Эталон и первичная видеозапись хранятся до удаления аккаунта. Удаление выполняется через устойчивое задание очистки. Резервные копии могут содержать прежние зашифрованные данные и должны обслуживаться по отдельной политике хранения/восстановления; семь дней относятся к рабочему хранилищу.

Согласие версии `intercity-face-2026-11-v2`, назначение и признак дополнительного водительского согласия сохраняются на сервере. Юридические реквизиты оператора и общая политика/оферта требуют отдельной актуализации; данный файл не заменяет юридические документы.

Обычные API и универсальные административные коллекции не выдают биометрические модели. Право `identity.review` проверяется строго, без разрешающего отката при ошибке RBAC. Просмотр материалов и решения записываются в аудит. В уведомления не передаются документы, снимки, телефон или векторы.

## Администратор

Раздел «Проверка личности»: очередь восстановления и документов (первичная привязка в неё не отправляется), исходная причина, пользователь, задания, видео/снимки, объяснение решения. Подтверждение недоступно без материалов и отметки об их просмотре. Для автомобиля администратор вводит данные непосредственно из документа.

«Включить push о новых проверках» запрашивает разрешение браузера и регистрирует устройство. После регистрации приходят фоновые Web Push; дополнительно работает счётчик/сообщение внутри админки. Отказ ОС/браузера нельзя обойти. Ссылка уведомления открывает очередь после проверки административной сессии или входа.

## Выпуск и проверки

Миграция `20261104180000_identity_verification` добавляет отдельные таблицы, разрешение и `identityVerificationEnabled=true`. Перед переключением производится стандартное сравнение исходников и резервное копирование; после старта проверяется внутренний модуль и отдельно сохраняются новые ключи. Выключатель — существующие AppSettings; непроверенное восстановление по одному телефону полностью удалено, даже при старой переменной ALLOW_UNVERIFIED_PASSWORD_RESET.

Проверки: PostgreSQL-потоки регистрации/сброса/документов, одноразовость и конкуренция, шифрование, чужое лицо/документ, ручная очередь, распознавание полей, отрицательные тесты движка в ограниченном контейнере, Flutter analyze/tests обоих интерфейсов, браузерная запись WebM и проверка экранов. Реальная положительная запись с физического телефона отдельно необходима для проверки качества на устройстве; синтетические тесты её не заменяют.

Android/iOS код камеры включён в исходники. Для уже установленного Android нужна новая подписанная публикация; ранее обнаруженное отсутствие upload-keystore/паролей в GitHub Actions остаётся внешним препятствием. Веб-версия публикуется независимо.

Распознавание движений: до 30 анализируемых кадров в секунду, два последовательных кадра для короткого движения, относительный порог открытия рта и небольшой подъём подбородка; допускается задержка реакции после команды. При первичной проверке умеренно смягчены пороги качества и PAD. При восстановлении сравнение лица и строгие пороги PAD сохраняются. Фото, статичное лицо и повтор записи не заменяют выполнение случайных заданий.

Восстановление: достаточно одного естественного моргания с закрытием и открытием глаз. При сходстве лица не ниже 0.70 пропуск одного из трёх жестов не требует ручной проверки, если два остальных распознаны, обе PAD-модели и проверки резкости/непрерывности лица уверенно пройдены. При этом основной порог автоматического совпадения лица остаётся 0.60, явное несовпадение по-прежнему запрещает сброс. Ошибки качества или живого лица не обходятся этим допуском.

Оптимизация обработки: поиск лица выполняется на копии кадра до 512 пикселей (для документов прежние 640); координаты движений вычисляются на кадре до 640 пикселей по длинной стороне, с сохранением частоты до 30 Гц. Полное разрешение остаётся для сравнения лица, PAD, резкости и эталона. Векторы лица рассчитываются по времени (не чаще одного раза в 350 мс), независимо от частоты камеры. При восстановлении новый пароль — минимум 6 символов, максимум 72 байта.
