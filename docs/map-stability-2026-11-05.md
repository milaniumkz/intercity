# Стабильность карты города и аукциона

Диагностика production: запросы поиска адресов и маршрутов в журнале завершались успешно, но GeoService регистрировал тайм-ауты Photon/Nominatim. Изображения OpenStreetMap загружались напрямую на устройства и исторически не попадали в серверный журнал. Серверная проверка двух участков OSM вернула PNG/HTTP 200; это не доказывает доступность из сети каждого телефона.

Видимый участок теперь проверяется отдельно от старых уже загруженных тайлов. После перемещения/масштабирования старый успех больше не скрывает пустую карту. Проверка по таймеру планирует новый кадр Flutter, чтобы сообщение и восстановление не зависели от движения пользователя. Ссылки на уничтоженные TileImage освобождаются.

При неудаче прямой загрузки приложение автоматически переключается на `/api/geo/tiles/:z/:x/:y.png`. Кэш получает только запрошенные изображения, без предзагрузки стран. Максимум 3000 файлов (очистка каждые 64 записи), 8 параллельных запросов к фиксированному OSM-host, ограниченная очередь и тайм-аут. Совпадающие запросы объединяются. Соблюдаются max-age и условная проверка ETag/Last-Modified; без заголовков срок 7 дней. При сбое источника допускается ранее сохранённое изображение с истечением не более суток. Ограничены масштаб и координаты, HTML вместо PNG не кэшируется, произвольные внешние URL не принимаются. В запросе указан User-Agent InterCity, атрибуция OSM сохранена. Кэш размещается в существующем закрытом technical-data, не является полной офлайн-картой Казахстана и России.

Автоматические попытки ограничены тремя с задержками 1/3/8 секунд; ручная кнопка остаётся доступной. События `client.map.load_failed` и `client.location.failed` различают карту, источник и геолокацию, не содержат адресов/координат/произвольных сообщений. Успешные отдельные изображения не создают по две записи аудита в базе. Серверные ошибки источника ограниченно журналируются.

Отказ браузера в геолокации больше не сохраняется на весь сеанс: короткая защита от повторных запросов истекает через 30 секунд, ручной повтор доступен сразу. Возврат из настроек при пустой точке подачи заново проверяет местоположение. Непредвиденный сбой устройства не отключает последующие попытки. Сбой уточнения адреса после полученной позиции не называется отказом GPS.

Проверки: тесты кэша (валидация, объединение запросов, работа сохранённых изображений без сети, ETag/304, отказ кэширования HTML, отсутствие аудита каждого изображения); widget-регрессии смены видимого участка и автоматического повтора; тесты геолокации/разрешений. В Chromium оба режима проверены с принудительным обрывом прямых tile-запросов после работающей карты: автоматическое восстановление через серверный кэш, без нажатий пользователя, ошибок JavaScript нет. Production-пользователи и заказы не изменялись.

Дополнительно повторено в Chromium через настоящий браузерный Geolocation API с выданным разрешением и координатами тестового устройства. Город: 70 прямых ответов до сбоя, затем 30 через сервер; аукцион: 61 прямой ответ, затем 34 через сервер. В обоих сценариях карта восстановилась автоматически, ошибок JavaScript нет. Источник PNG проверен непосредственно с production VPS: HTTP 200 для обзорного и уличного масштаба. Полная карта стран не устанавливалась.

Итоговые локальные проверки: Flutter analyze без замечаний; 385 тестов приложения пройдено, 9 пропущено. Исправлена также гонка подписки на уже уничтоженный TileImage, воспроизведённая тестом выбора точки на карте. Backend: 111 тестов пройдено, 37 пропущено (интеграционные выполняются отдельно в CI).
