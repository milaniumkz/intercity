# Восстановление доступа

Автоматическое восстановление по телефону сейчас не подключено. Публичный экран «Забыли пароль?» сразу сообщает об этом, принимает только номер аккаунта и копирует текст обращения администратору. Пользователь сам передаёт обращение через действующий канал связи; копирование не создаёт заявку и не меняет пароль. Полей нового пароля и запроса к `/auth/reset-password` на этом экране нет.

Администратор с доступом к технической панели после подтверждения владельца находит аккаунт и использует существующее действие выдачи временного пароля. Операция требует повторной аутентификации администратора и причины, фиксируется в аудите, отзывает сессии и выставляет `mustChangePassword`. При первом входе пользователь обязан заменить временный пароль. Обычный сотрудник без соответствующего технического доступа выполнять эту операцию не может. Временный пароль передаётся только подтверждённому владельцу через согласованный канал, не помещается в репозиторий или отчёт.

Вошедший пользователь, знающий текущий пароль, меняет его через «Профиль → Настройки → Безопасность». Для автоматического восстановления необходим отдельный подтверждённый канал владения аккаунтом; данное исправление его не подключает. Флаг `ALLOW_UNVERIFIED_PASSWORD_RESET` не включается.

Проверка изменения: `flutter analyze` без замечаний; `flutter test` — 332 пройдено, 9 пропущено. Новые проверки покрывают светлую/тёмную тему, отсутствие полей нового пароля, валидацию номера перед копированием, содержимое обращения, возврат ко входу и доступность действий на 320×568 с открытой клавиатурой. Схема БД и существующие пароли не меняются.
