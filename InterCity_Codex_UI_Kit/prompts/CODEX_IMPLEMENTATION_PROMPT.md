## 1. Цель

Реализовать полный мобильный UI сервиса InterCity в двух темах:

- светлая тема;

Стиль: премиальный, дорогой, простой, удобный, фиолетовый брендовый акцент. Приложение должно выглядеть как солидный сервис такси/межгорода/доставки, а не как дешёвое такси.

## 3. Критичная бизнес-логика

### 3.1. Город → Легковой / fixed fare

- Пассажир вводит точку А и точку В.
- Нужны координаты обеих точек.
- Система строит маршрут и считает цену.
- Внизу сразу показывается стоимость.
- Доступен выбор класса авто:
  - Эконом;
  - Оптимал;
  - Комфорт;
  - Бизнес.
- Цена меняется при изменении маршрута и класса.
- Доступные способы оплаты:
  - наличными;
  - на карту;
  - бонусами.
- Ручной адрес без координат в этом режиме не разрешать, потому что системе нужен маршрут для цены.
- Если карта не находит адрес — предложить уточнить, выбрать точку на карте или перейти в Аукцион.

### 3.2. Город → Аукцион

- Пассажир вводит точку А и точку В.
- Цена пассажиром не указывается.
- Система цену не считает.
- Класс авто не выбирается.
- Водители предлагают свою цену.
- Пассажир выбирает одно предложение.
- Доступные способы оплаты:
  - наличными;
  - на карту;
  - бонусами.
- Ручной ввод адреса разрешён, если карта не нашла адрес.
- Водителю показывать бейдж: `Адрес введён вручную`, если координаты не подтверждены.

### 3.3. Межгород

- Не делать отдельный режим Аукцион.
- Пассажир создаёт межгородскую заявку.
- Водители видят заявку и предлагают/принимают условия по текущей бизнес-логике проекта.
- Добавить способ оплаты:
  - наличными;
  - на карту;
  - бонусами.
- Ручной адрес разрешён, если карта не нашла точку.
- Водителю показывать способ оплаты и предупреждение о ручном адресе.

### 3.4. Доставка

- Отдельный режим: Доставка по городу / Межгород / По РФ.
- Бонусы в доставке НЕ показывать и НЕ подключать.
- Оплата доставки:
  - наличными;
  - на карту.
- Ручной адрес разрешён.
- Поля доставки:
  - тип доставки;
  - откуда забрать;
  - куда доставить;
  - описание груза;
  - вес/размеры, если поддерживается;
  - фото груза, если уже есть upload;
  - дата/время забора;
  - комментарий;
  - контакт получателя, если есть.

### 3.5. Списание с баланса водителя за межгород

Проверь, реализовано ли списание со счёта водителя за фактически принятую межгородскую заявку. Если нет — реализуй.

Требования:

- Списывать только за принятую заявку.
- Не списывать за просмотр.
- Не списывать за отклик, если пассажир/система не приняла водителя.
- Не списывать повторно при refresh, retry API или повторном accept.
- Списание должно быть идемпотентным.
- Создавать транзакцию в истории баланса.
- Если средств мало — показывать экран/ошибку недостаточно средств и CTA пополнить баланс.

### 3.6. Адреса и карта

Исправь проблему, когда вместо адреса показываются цифры координат.

Сделай единый форматтер:

```ts
formatLocationDisplay(location)
```

Приоритет отображения:

1. `manualAddress`;
2. `addressLabel` / `formattedAddress` / `displayName`;
3. reverse-geocoded readable address;
4. `Выбранная точка на карте`;
5. координаты только как технический fallback и только с подписью.

Нельзя показывать пользователю просто `43.238293, 76.945465` вместо адреса.
